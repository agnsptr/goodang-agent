# GOODANG CI & BRANCH PROTECTION SPECIFICATION

**Project:** Goodang
**Component:** Autonomous Customer Service Agent
**Document Type:** CI Pipeline & Branch Protection Standard
**Version:** 1.0
**Status:** Authoritative — Fase 1 Foundation

> **Canonical Contract:** Nama state, tool, activity, error code, dan schema field didefinisikan kanonik di `docs/0. GOODANG_CONTRACT.md` (Single Source of Truth). Dokumen ini adalah SoT untuk **CI pipeline & branch protection**. Jika ada konflik nama, `docs/0` menang.

## 1. Tujuan

Dokumen ini mendefinisikan standard CI/CD pipeline dan branch protection untuk Goodang, diadaptasi dari standard ENTIGI:

- **SOP-ENT-DEV-004** — AI Code Review & PR Guardrail
- **WI-ENT-DEV-002** — branch protection
- **WI-ENT-DEV-003** — Menulis Aturan Bug untuk CodeRabbit
- **BA-ENT-DEV-004** — AI-Powered Code Review & PR Guardrail

Stack Goodang = Python + Google ADK + Temporal + Supabase (bukan Laravel), jadi pipeline diadaptasi: ruff/mypy/bandit/pytest (bukan Pint/Larastan/PHPUnit).

## 2. Tiga Lapis Review (sesuai SOP-ENT-DEV-004)

```text
PR dibuka
  ↓
[1] GitHub Actions (Hard Gate Deterministik)
    - contract drift check
    - tool registry sync
    - yaml lint
    - ruff (lint)
    - mypy (type check)
    - bandit (security)
    - secret detection
    - pytest (tests)
    - docker compose validate
  ↓ (gagal = block merge)
[2] CodeRabbit (AI Pre-Review Kontekstual)
    - baca docs/rules/ sebagai knowledge base
    - P0 → request changes
    - P1 → comment
    - P2 → suggestion
  ↓ (P0 unresolved = Guardian tolak)
[3] Library Guardian (Human Review Final)
    - verify hard gate lulus
    - verify P0 CodeRabbit resolved
    - approve atau request changes
  ↓
Merge (squash, linear history)
```

**Aturan:** CodeRabbit TIDAK menggantikan Guardian. Guardian TIDAK menggantikan hard gate. Ketiga lapis wajib lulus.

## 3. CI Pipeline (`.github/workflows/ci.yml`)

### 3.1 Jobs (9 jobs, semua required)

| Job | Tool | Fungsi | Fase |
|:--|:--|:--|:--|
| `contract-drift` | `scripts/check-contract-drift.sh` | Cek integritas `docs/0` SoT | Fase 1 ✅ |
| `tool-registry-sync` | `scripts/check-tool-registry-sync.py` | Cek sync registry ↔ kontrak | Fase 1 ✅ |
| `yaml-lint` | `yamllint` | Validasi workflow & config YAML | Fase 1 ✅ |
| `python-lint` | `ruff` | Lint Python code | Fase 1 (skip jika no .py) |
| `python-typecheck` | `mypy` | Type check Python | Fase 1 (skip jika no .py) |
| `security-scan` | `bandit` + grep | Security + secret detection | Fase 1 ✅ |
| `tests` | `pytest` | Unit/integration tests | Fase 1 (stub), Fase 2+ wajib |
| `docker-validate` | `docker compose config` | Validasi compose file | Fase 1 ✅ |
| `ci-summary` | aggregator | Status check untuk branch protection | Fase 1 ✅ |

### 3.2 Trigger

- `pull_request` ke `main` / `develop`
- `push` ke `main` / `develop`

### 3.3 Skip condition (Fase 1 spec-only repo)

Jobs `python-lint`, `python-typecheck`, `tests` skip otomatis kalau belum ada file Python/tests. Fase 2+ wajib ada.

### 3.4 Contract drift workflow (`.github/workflows/contract.yml`)

Workflow terpisah untuk contract drift check (sudah ada sebelumnya). Trigger di PR yang sentuh `docs/`, `app/**/*.md`, `app/tools/registry.yaml`, `scripts/check-*.py`.

## 4. CodeRabbit AI Review (`.coderabbit.yaml`)

### 4.1 Config

- **Profile:** `assertive` (request changes untuk P0)
- **Auto-review:** enabled, skip drafts
- **Knowledge base:** `docs/rules/**/*.md` (di repo ini, bukan Standard Documentation)
- **Path instructions:** per-folder (`app/agents/`, `app/temporal/`, `app/tools/`, dll)

### 4.2 Severity mapping

| Severity | Aksi CodeRabbit | Bypass? |
|:--|:--|:--|
| P0 | Request changes (block merge via `request_changes_workflow`) | Tidak |
| P1 | Comment (tidak block) | Ya, Guardian override |
| P2 | Suggestion | Ya |

### 4.3 P0 categories (sesuai `.coderabbit.yaml`)

- Class D tools di ADK layer
- `SUPABASE_SERVICE_ROLE_KEY` di ADK/App Layer container
- Direct DB mutation ADK → `pos_transaction_log`
- Ghost states (`WAITING_CUSTOMER`, `CUSTOMER_CONFIRMATION`, `VALIDATION`)
- Forbidden tool names (`lookup_customer`, `add_item`, `cancel_draft`, dll)
- Forbidden error codes (`RESOLVED`, `VALID`, `UNAVAILABLE`, `HANDOVER`)
- Secrets in code
- `time.sleep` / `asyncio.sleep` di Temporal workflow
- UPDATE/DELETE pada `pos_transaction_log`
- Prompt injection vectors
- PII di log plaintext

### 4.4 Setup

1. Install CodeRabbit GitHub App ke repo (https://github.com/apps/coderabbitai)
2. Commit `.coderabbit.yaml` di root repo
3. CodeRabbit auto-review tiap PR

## 5. Knowledge Base (`docs/rules/`)

### 5.1 Format (sesuai WI-ENT-DEV-003)

Setiap file `docs/rules/bug-[slug].md` wajib:

- Severity: P0 / P1 / P2
- Don't + Do
- Contoh SALAH + BENAR
- Tidak mengandung secret
- Ringkas

### 5.2 Seed rules (Fase 1)

| File | Severity | Konteks |
|:--|:--|:--|
| `bug-class-d-in-adk.md` | P0 | Class D tools di ADK |
| `bug-service-role-in-adk.md` | P0 | service_role di ADK container |
| `bug-pos-tl-mutation.md` | P0 | UPDATE/DELETE pos_transaction_log |
| `bug-time-sleep-in-workflow.md` | P0 | time.sleep di workflow |
| `bug-ghost-state-usage.md` | P0 | Ghost state names |
| `bug-forbidden-tool-name.md` | P0 | Forbidden tool names |

### 5.3 Tambah rule baru

Saat bug kritis di-fix, buat rule pencegahan dalam 1 hari kerja (SOP-ENT-DEV-004 §5.4):

1. Buat `docs/rules/bug-[slug].md`
2. Commit di PR yang sama dengan fix, atau PR terpisah
3. CodeRabbit baca rule di PR berikutnya

## 6. Branch Protection Rules

### 6.1 Apply via script

```bash
# Dry-run (preview payload)
DRY_RUN=1 bash scripts/setup-branch-protection.sh

# Apply ke repo dari git remote
bash scripts/setup-branch-protection.sh

# Apply ke repo explicit
bash scripts/setup-branch-protection.sh owner/repo

# Custom branch
BRANCH=develop bash scripts/setup-branch-protection.sh
```

### 6.2 Rules yang di-apply

| Rule | Value | Alasan |
|:--|:--|:--|
| Required status checks | 9 contexts (CI jobs) | Hard gate wajib lulus |
| Strict (branch up-to-date) | true | PR wajib rebase ke head branch terbaru |
| Required reviews | 1 | Min 1 approving review |
| Code owner reviews | true | `CODEOWNERS` enforce |
| Dismiss stale reviews | true | Push baru dismiss approval lama |
| Linear history | true | Squash merge, no merge commits |
| Allow force push | false | Branch tidak bisa di-force-push |
| Allow deletions | false | Branch tidak bisa di-delete |
| Block creations | false | Branch bisa dibuat (untuk develop) |
| Enforce admins | true | Admin juga kena aturan |
| Conversation resolution | true | Semua thread comment wajib resolved |

### 6.3 Required status checks

```text
- Contract Drift Check
- Tool Registry Sync
- YAML Lint
- Python Lint (ruff)
- Python Type Check (mypy)
- Security Scan (bandit + secrets)
- Tests (pytest)
- Docker Compose Validate
- CI Summary (Required)
```

### 6.4 Self-merge protection

Kombinasi `require_code_owner_reviews=true` + `required_approving_review_count=1` + `CODEOWNERS` yang cover semua path → **self-merge dilarang**. PR author tidak bisa approve PR sendiri.

## 9. Workflow GitHub Actions

### 9.1 `ci.yml` (main pipeline)

9 jobs, semua required. Run di PR dan push ke main/develop.

## 10. Setup Procedure (Fase 1)

### 10.1 One-time setup

```bash
# 1. Install CodeRabbit GitHub App
#    https://github.com/apps/coderabbitai → install ke repo goodang-agent

# 2. Create GitHub teams di org
gh api --method POST /orgs/ENTIGI/teams -f name=guardians -f privacy=closed
gh api --method POST /orgs/ENTIGI/teams -f name=tech-leads -f privacy=closed
gh api --method POST /orgs/ENTIGI/teams -f name=devops -f privacy=closed
# ... dst

# 3. Add members ke team
gh api --method PUT /orgs/ENTIGI/teams/guardians/memberships/username

# 4. Update CODEOWNERS dengan team slug aktual
#    (ganti @goodang/guardians → @ENTIGI/guardians, dll)

# 5. Apply branch protection
bash scripts/setup-branch-protection.sh ENTIGI/goodang-agent

# 6. Verify
gh api /repos/ENTIGI/goodang-agent/branches/main/protection | jq .
```

### 10.3 Personal repo (agnsptr / GitHub Free)

```bash
# Branch protection pada private repo butuh GitHub Pro.
# Opsi A: repo public (free tier)
gh repo edit owner/goodang-agent --visibility public --accept-visibility-change-consequences

# Opsi B: tetap private + upgrade GitHub Pro

# Apply protection — solo maintainer (CI gate, tanpa Guardian approval)
SOLO=1 bash scripts/setup-branch-protection.sh owner/goodang-agent

# Update CODEOWNERS ke @owner (bukan @goodang/guardians)
```

### 10.2 Per-PR flow

```text
1. Developer buat branch feature/xxx dari main
2. Commit + push branch
3. Buka PR ke main
4. CI auto-run (9 jobs)
5. CodeRabbit auto-review (P0/P1/P2)
6. Guardian review (code owner)
7. Resolve conversations
8. Guardian approve
9. Squash merge (linear history)
10. Branch auto-delete
```

## 11. Hotfix Flow (exception)

Sesuai WI-ENT-DEV-002, hotfix darurat:

```text
1. Branch hotfix/xxx dari main
2. PR dengan label "hotfix"
3. CI wajib lulus (no bypass)
4. Guardian bisa approve langsung (1 review cukup)
5. Security-scan wajib lulus (no bypass)
6. Merge
7. Rule docs/rules/ wajib dilengkapi dalam 1 hari kerja
```

**Dilarang:** bypass CI, bypass security-scan, self-merge hotfix.

## 12. Compliance & Audit

### 12.1 Audit trail

- Setiap PR: CI logs (retained 90 hari), CodeRabbit review comment (persistent), Guardian approval (persistent)
- Branch protection change: tercatat di GitHub audit log
- Merge: squash commit dengan PR reference

### 12.2 Review SLA (sesuai SOP-ENT-DEV-003)

| Severity | First response | Resolution |
|:--|:--|:--|
| P0 PR (security) | 2 jam | 8 jam |
| P1 PR (fitur utama) | 1 hari kerja | 3 hari kerja |
| P2 PR (minor) | 3 hari kerja | 1 minggu |

### 12.3 Metrics

- `pr_review_time_hours` — waktu dari PR open sampai merge
- `p0_open_count` — PR dengan P0 unresolved
- `coderabbit_p0_rate` — % PR dengan P0 dari CodeRabbit
- `ci_failure_rate` — % PR dengan CI gagal
