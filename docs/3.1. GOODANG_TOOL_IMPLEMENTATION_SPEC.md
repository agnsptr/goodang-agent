# GOODANG TOOL IMPLEMENTATION SPEC

**Project:** Goodang  
**Component:** ADK Tool Implementation Layer  
**Channel:** Telegram  
**Agent Framework:** Google Agent Development Kit (ADK)  
**Workflow Engine:** Temporal  
**Primary Business Process:** CS Goodang — Guru Ingin Pesan  
**Primary Transaction Log:** `POS_TRANSACTION_LOG`  
**Document Type:** Tool Implementation Specification  
**Version:** 1.0  
**Status:** Development Baseline — production endpoints/schema require environment verification

---

# 1. Purpose

Dokumen ini menerjemahkan:

```text
GOODANG_TOOL_CONTRACT.md
GOODANG_DATA_CONTRACT.md
GOODANG_SYSTEM_INVENTORY.md
GOODANG_ADK_IMPLEMENTATION_SPEC.md
GOODANG_TEMPORAL_WORKFLOW_SPEC.md
GOODANG_STATE_MACHINE.md
```

menjadi blueprint implementasi konkret untuk setiap tool ADK dan integration adapter.

Tujuan:

1. menentukan struktur kode setiap tool;
2. menentukan source of truth;
3. menentukan request/response contract;
4. menentukan permission;
5. menentukan side effect;
6. menentukan retry/timeout;
7. menentukan idempotency;
8. menentukan mapping ADK → backend;
9. menentukan mapping tool → Temporal;
10. mencegah developer/Hermes menebak endpoint atau schema yang belum diverifikasi.

---

# 2. Critical Rule: Verified vs TBD

Dokumen ini menggunakan tiga status:

```text
CONFIRMED
```

Artinya didukung oleh dokumentasi Goodang yang tersedia.

```text
TARGET
```

Artinya merupakan architecture target yang telah dipilih.

```text
TBD / VERIFY
```

Artinya detail implementasi nyata belum tersedia dan harus diperiksa dari environment/backend Goodang.

Rules:

```text
TBD ≠ permission to invent
```

Jika endpoint, database table, authentication, atau field backend belum diketahui:

```text
inspect
→ verify
→ document
→ implement
```

Jangan langsung membuat asumsi production.

# 6. Common Response Envelope

Use:

```json
{
  "ok": true,
  "code": "SUCCESS",
  "data": {},
  "correlation_id": "..."
}
```

Error:

```json
{
  "ok": false,
  "code": "PRODUCT_NOT_FOUND",
  "data": null,
  "correlation_id": "..."
}
```

The agent makes decisions using:

```text
code
```

not only natural-language messages.

# 33. Final Mutation: `write_pos_transaction_log`

Do not expose as ADK tool.

Architecture:

```text
Transaction Service
       ↓
POS_TRANSACTION_LOG
```

The transaction log has 17 documented fields. fileciteturn2file6L950-L972

Mapping:

```text
transaction_id    ← Transaction Service
transaction_date  ← System / order date
outlet_code       ← Active Outlet
member_id         ← Member Master
member_name       ← Member Master
payment_method    ← Payment Rule
sku_code          ← Product Master
product_name      ← Product Master
uom               ← Product Master
qty               ← Confirmed Order
cooked_qty        ← Business Rule
selling_price     ← Price Master
service_fee       ← Business Rule
line_amount       ← System calculation
remarks           ← Customer / CS
created_by        ← CS / Agent identity
created_at        ← System timestamp
```

This mapping is also documented in the existing SOP/WI. fileciteturn2file0L106-L126

