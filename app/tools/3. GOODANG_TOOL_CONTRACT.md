# GOODANG TOOL CONTRACT

**Project:** Goodang  
**Component:** ADK Agent Tool Layer  
**Channel:** Telegram  
**Agent Framework:** Google Agent Development Kit (ADK)  
**Workflow Engine:** Temporal  
**Primary User:** Guru / staff Goodang  
**Business Process:** CS Goodang — Guru Ingin Pesan  
**Primary Transaction Log:** `POS_TRANSACTION_LOG`  
**Document Type:** Tool Contract  
**Version:** 1.0

---

# 1. Purpose

Dokumen ini mendefinisikan kontrak teknis untuk semua tools yang dapat digunakan oleh Goodang ADK Agent.

Tujuan utama:

1. memastikan agent hanya menggunakan tool yang sesuai;
2. memastikan input/output tool memiliki schema yang jelas;
3. memisahkan operasi **read**, **draft mutation**, dan **final transaction mutation**;
4. memastikan agent tidak mengarang data;
5. memastikan transaksi final hanya berjalan melalui Temporal/Goodang backend;
6. memastikan setiap tool dapat divalidasi, diuji, diaudit, dan dikembangkan secara konsisten.

# 3. Core Tool Principles

## Rule TOOL-001 — No Guessing

Tool digunakan untuk memperoleh fakta dari source of truth.

Agent tidak boleh mengganti hasil tool dengan asumsi.

```text
Tool says NOT_FOUND
→ Agent MUST NOT say FOUND

Tool says UNKNOWN
→ Agent MUST NOT invent result

Tool unavailable
→ Agent MUST NOT fabricate result
```

---

## Rule TOOL-002 — Source of Truth

Setiap data harus berasal dari source yang sesuai.

| Data | Source |
|---|---|
| Customer | Member Service / Member Master |
| Product | Product Master |
| Price | Price Master |
| Stock | Stock Service |
| Payment / Plafon | Payment Service |
| Order | Order Service / Temporal |
| Transaction | Transaction Service |
| Final transaction log | `POS_TRANSACTION_LOG` |

---

## Rule TOOL-003 — Least Privilege

Tool hanya boleh memiliki access scope yang diperlukan.

Contoh:

```text
search_product()
```

boleh membaca Product Master.

Tetapi tidak boleh:

```text
update_product()
delete_product()
```

---

## Rule TOOL-004 — Transaction Boundary

ADK Agent tidak boleh langsung:

```text
INSERT transaction
UPDATE transaction
DELETE transaction
UPDATE POS_TRANSACTION_LOG
DEDUCT stock
EXECUTE payment
```

Final mutation harus:

```text
ADK
 ↓
Temporal
 ↓
Goodang Transaction/Stock/Payment Service
```

# 4. Tool Classification

## Class A — Read Tools

Read-only. Aman dipanggil agent untuk mendapatkan fakta.

```text
identify_customer
get_customer
search_product
get_product
get_price
check_stock
get_plafon
get_payment_status
get_order
get_order_history
```

---

## Class B — Draft Tools

Mengubah Order Draft tetapi belum membuat final transaction.

```text
create_draft_order
update_draft_order
add_order_item
remove_order_item
get_order_draft
```

Draft mutation harus tetap mengikuti active order/workflow.

---

## Class C — Workflow Command Tools

Mengirim command ke Temporal/application layer.

```text
start_order_workflow
confirm_order
cancel_order
request_human_handover
```

---

## Class D — Final Mutation

Tidak boleh menjadi unrestricted LLM tool.

```text
create_transaction
deduct_stock
execute_payment
```

Operasi ini dikendalikan Temporal/Goodang backend.

# 6. Common Response Envelope

Recommended response:

```json
{
  "ok": true,
  "code": "SUCCESS",
  "message": "Operation completed",
  "data": {},
  "correlation_id": "..."
}
```

Failure:

```json
{
  "ok": false,
  "code": "PRODUCT_NOT_FOUND",
  "message": "Product not found",
  "data": null,
  "correlation_id": "..."
}
```

Agent harus menggunakan `code` untuk keputusan, bukan hanya `message`.

# 7. Customer Tools

## 7.1 `identify_customer`

### Purpose

Mencari customer Goodang berdasarkan identity yang tersedia.

### Permission

```text
READ
```

### Input

```json
{
  "telegram_user_id": "123456789",
  "telegram_chat_id": "123456789",
  "phone": null,
  "member_id": null,
  "name": null
}
```

Field dapat bersifat optional sesuai source yang tersedia.

### Output — Found

```json
{
  "ok": true,
  "code": "CUSTOMER_FOUND",
  "data": {
    "member_id": "MBR-050",
    "member_name": "Imam Nurhadi"
  }
}
```

### Output — Not Found

```json
{
  "ok": false,
  "code": "CUSTOMER_NOT_FOUND",
  "data": null
}
```

### Agent Behavior

Jika `CUSTOMER_FOUND`:

```text
continue
```

Jika `CUSTOMER_NOT_FOUND`:

```text
ask identity
OR
handover
```

Tidak boleh membuat ID sendiri.

# 9. Product Tools

### Purpose

### Input

```json
      {
        "sku_code": "SKU-001",

      }
    ]
  }
}
```

```json

  "ok": true,

        "sku_code": "SKU-001",
```

```json
{
  "ok": false,

  "data": {

}
```

### Agent Behavior

```text

→ continue

>1 match
→ ask customer

→ clarification / alternative / handover
```

Agent tidak boleh memilih kandidat random.

# 35. Tool Selection Matrix

| User Request | Tool |
|---|---|
| "Siapa data member saya?" | `identify_customer` / `get_customer` |
| "Ada beras?" | `search_product` + `check_stock` |
| "Berapa harga beras?" | `search_product` + `get_price` |
| "Stok beras berapa?" | `search_product` + `check_stock` |
| "Pesan beras 2" | customer + product + stock + price + draft |
| "Tambah 2 minyak" | `get_order_draft` + product + stock + price + update |
| "Batal kopi" | `get_order_draft` + `remove_order_item` |
| "Berapa total pesanan?" | `get_order_draft` |
| "Ya, pesan" | `confirm_order` jika state valid |
| "Batal semua" | `cancel_order` |
| "Pesan seperti biasa" | `get_order_history` |
| "Saya mau bicara dengan CS" | `request_human_handover` |

---

# 36. Prohibited Tool Selection

Agent tidak boleh:

```text
call transaction tool to answer price question
call stock mutation to answer stock question
call payment execution to check payment
write transaction when customer asks for draft
deduct stock during stock inquiry
```

# 43. Tool Response to Customer Mapping

Tool result must be translated into customer language.

Example:

```text
INSUFFICIENT_STOCK
```

becomes:

> "Stok saat ini hanya tersedia 3 pcs. Apakah mau pesan 3 pcs?"

Not:

> "Error INSUFFICIENT_STOCK."

---

# 44. Tool Response Must Not Be Exposed Blindly

Internal:

```json
{
  "code": "SERVICE_UNAVAILABLE",
  "correlation_id": "abc123",
  "upstream": "stock-service",
  "http_status": 503
}
```

Customer should receive:

> "Saya belum bisa mengecek stok saat ini karena sistem sedang mengalami kendala."

Do not expose internal hostnames, stack traces, or infrastructure details.

# 51. Non-Negotiable Rules

```text
1. No guessing.
2. No direct database transaction mutation.
3. No unrestricted transaction tool.
4. No transaction before confirmation.
5. No stock deduction before transaction.
6. No price without Price Master.
7. No stock claim without Stock Service.
8. No payment claim without Payment Service.
9. No ambiguous product selection.
10. No duplicate side effect.
11. No bypass Temporal.
12. No false success message.
13. No secret exposure.
14. No historical transaction cloning without confirmation.
15. Every mutation must be auditable.
```
