```text

```

```text

Workflow code must be deterministic.

Do not call external systems directly from Workflow code:

```text

Telegram API

```text

```text

# 22. Transaction Activity — `create_transaction`

This Activity is controlled by Temporal and is not an unrestricted ADK tool.

  "payment_method": "PLAFON",

```json

  "ok": true,
  "code": "TRANSACTION_CREATED",
  "data": {

# 58. Transaction Crash Recovery

Scenario:

```text
create_transaction succeeds
response lost
worker crashes
worker restarts
```

Required:

```text
retry create_transaction
→ idempotency key
→ existing transaction returned
```

Then:

```text
deduct_stock
```

---

# 59. Stock Crash Recovery

Scenario:

```text
deduct_stock succeeds
response lost
worker crashes
```

Required:

```text
retry deduct_stock
→ same transaction_id/idempotency key
→ existing deduction recognized
```

Do not double deduct.

```text

```

The system must use a business-defined compensation/reconciliation workflow:

```text

```

# 61. Concurrency

The same order must not be modified by two independent mutation paths at the same time.

All mutations should be serialized through the Workflow.

Example:

```text
ADD_ITEM
UPDATE_ITEM
CANCEL
CONFIRM
```

must obey current state.

---

# 62. Illegal Transition Handling

Any undefined transition:

```text
INVALID_TRANSITION
```

Examples:

```text
BUILDING_ORDER
→ COMPLETED

CHECKING_STOCK
→ CONFIRMED

WAITING_CONFIRMATION
→ UPDATING_STOCK
```

These must never execute.

# 63. State Invariants

## INV-001

```text
state != WAITING_CONFIRMATION
→ "YA" cannot finalize order
```

## INV-002

```text
customer_confirmed != true
→ create_transaction forbidden
```

## INV-003

```text
transaction_id absent
→ COMPLETED forbidden
```

## INV-004

```text
transaction success absent
→ stock deduction forbidden
```

## INV-005

```text
ambiguous SKU
→ final transaction forbidden
```

# 90. Non-Negotiable Rules

```text
1. Workflow state belongs to Temporal.
2. Workflow code must remain deterministic.
3. External I/O belongs in Activities.
4. No transaction without customer confirmation.
5. No stock deduction before authorized transaction step.
6. Transaction creation must be idempotent.
7. Stock deduction must be idempotent.
8. Duplicate Telegram updates must be harmless.
9. Illegal state transitions must fail closed.
10. Business errors must not retry indefinitely.
11. Worker restart must not lose workflow state.
12. Final success must reflect actual backend state.
13. ADK must not bypass Temporal.
14. ADK must not write POS_TRANSACTION_LOG directly.
15. Unknown backend behavior must remain TBD until verified.
16. Workflow changes require compatibility/versioning review.
17. Every production incident becomes a regression test.
